--------------------------------------------------------------------------------
0. WHAT THE JOB IS (in one paragraph)
--------------------------------------------------------------------------------
A student submits ONE big PDF (or a folder of PDFs/images) containing many
different documents scanned together — passport, NID, birth certificate,
academic certificates + transcripts, apostilles, business/tax papers, etc.
Your job is to (1) RECOGNIZE what each page is, (2) SPLIT the big PDF into the
correct document groups, and (3) MERGE the pages that belong together into a
single, correctly-named PDF per document. The final output is a clean folder
where each file is one real-world document with a proper bilingual
(Korean-English) name.

    ONE messy PDF  ->  RECOGNIZE each page  ->  SPLIT into groups  ->  MERGE
    each group  ->  NAME each merged PDF in Korean-English.

--------------------------------------------------------------------------------
2. HOW RECOGNITION WORKS TODAY
--------------------------------------------------------------------------------
- Each page is rendered to an image (PyMuPDF / fitz) and sent to GPT-4o Vision.
- When template_pairs is provided (list of (english, korean) pairs from
  document_rename_merged_pairs()), GPT-4o is given the ENTIRE template list and
  must return the EXACT matching label — no hardcoded mapping. The output
  filename stem is built directly from the matched Korean-English pair.
- Legacy fallback: hardcoded keyword matching (DOC_TYPE_KEYWORDS) + optional
  Korean translation API when no template_pairs are supplied.
- Requires an OpenAI API key (gpt4o_api_key) and PyMuPDF installed.

--------------------------------------------------------------------------------
3. HOW SPLIT + MERGE GROUPING WORKS TODAY (the rules to preserve)
--------------------------------------------------------------------------------
After every page has a label, pages are GROUPED and MERGED by these rules:

  a) CONSECUTIVE same-label pages  -> merged into one PDF.

  b) BUSINESS BUNDLE — adjacent pages whose English label contains any of:
       "trade license", "business registration", "tin certificate",
       "tax certificate", "tax return acknowledgment",
       "acknowledgement certificate", "employment certificate"
     are merged into ONE PDF regardless of inter-page ordering.

  c) ACADEMIC LEVEL — all docs at the same level merge into one PDF
     (certificate + transcript + apostille + no-apostille together):
       ssc      : ssc, secondary school, middle school, o level
       hsc      : hsc, higher secondary, high school, a level
       bachelor : bachelor, undergraduate, b.sc, b.a., b.eng, degree certificate

  d) APOSTILLE — an apostille page is merged INTO its matched document with the
     apostille page(s) placed FIRST, then the document (see apostille_matcher).

Output name = Korean-English stem built from the matched template pair.

4. WHAT TO IMPROVE / FIX (open work — pick from here)
--------------------------------------------------------------------------------
Known issues from the test reports (FEATURE_AUDIT.txt, UNWIRED_FEATURES_TEST_
REPORT.md). Address these carefully:

  [BUG] get_pdf_page_count returns 0 with ok:true for a missing / broken PDF or
        when fitz is unavailable. Bulk-split then SILENTLY skips broken files.
        Fix: return an explicit error instead of 0 so nothing is skipped silently.

  [ROBUSTNESS] If GPT-4o returns a label NOT in the template list, do not guess.
        Fall the page back to fallback_prefix ("page") and flag it for human
        review rather than merging it into the wrong group.

  [ACCURACY] Recognition confidence: keep the CONFIDENCE_THRESHOLD = 60 idea.
        Below threshold => do NOT auto-merge; leave the page as its own file
        with a name that makes the uncertainty obvious.

  [SAFETY OF ORDER] Never reorder pages inside a single real document. Only
        group across documents. Apostille-first is the one intentional reorder.

  [IDEMPOTENCE] Re-running the pipeline on an already-processed folder must not
        double-merge or corrupt names.

--------------------------------------------------------------------------------
5. ACCEPTANCE CRITERIA (how we know it worked)
--------------------------------------------------------------------------------
  1. Every input page ends up in exactly one output PDF (no lost pages).
  2. Each output PDF is one real-world document (or one intended bundle).
  3. Filenames are the correct Korean-English pair from the template.
  4. Broken/unreadable pages are surfaced, never silently dropped.
  5. Low-confidence pages are separated for human review, not misfiled.
  6. Running twice produces the same result (idempotent).
  7. The ORIGINAL input file is never deleted or overwritten (see section 6).
