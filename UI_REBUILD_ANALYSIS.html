Support Modules

watch_folder_service.py
Background service — keep as-is
  • WatchFolderService — thread-based directory monitor
  • WatchEntry — queue item data class (name, status, elapsed)
  • Calls pdf_smart_split_merge_rename() on new files
  • Bridge: expose get_entries(), active_count(), clear_completed(), requeue_errors()
qr_screen_capture.py
Screen capture — bridge only
  • QRDecoder — pyzbar/OpenCV QR decode
  • OverlaySelector — drag-select screen region (needs native window)
  • OneClickOverlay — single-click capture
  • Bridge: run_drag_select() and run_pick_mode() launch overlay, return URL
  • ⚠ PyWebView cannot open native overlays from HTML — bridge must spawn these as separate Tkinter windows or system overlays
ai_photo_editor.py
AI image editing — rewrite UI layer
  • AIPhotoEditorFrame — Tkinter Frame (16 methods)
  • 15 helper functions: mask building, cost estimation, OpenAI client
  • Calls OpenAI DALL-E API for background removal / replacement
  • Bridge: expose run_ai_photo_action(path, action, mask_type) → returns output path
excel_grid.py
Excel viewer/editor — rewrite UI layer
  • ExcelGridFrame — Tkinter Frame (128 methods) using tksheet
  • Full cell editing, formatting, sorting, filtering, freeze panes
  • Backend: file_ops.py excel_* functions handle actual data
  • New UI: Handsontable or AG-Grid (JS) receiving data via bridge

Bridge Class — SFMBridge

A single Python class SFMBridge wraps all backend calls and is passed to webview.create_window(js_api=bridge). JavaScript calls await window.pywebview.api.METHOD(args).

Migration Plan — Phases

1

Bridge Layer (sfm_bridge.py)

Create sfm_bridge.py — thin wrapper class exposing all file_ops.py public functions as JSON-returning methods. Handle threading (long ops use async/callback pattern). No logic changes to backend.

~400 lines · Backend untouched · Testable independently

2

App Shell (main.py → pywebview entry)

Replace _main() in student_folder_maker.py with a PyWebView launcher. Load ui/index.html with the bridge. Keep all existing imports working so the backend chain is intact.

~50 lines

3

HTML Shell + CSS Design System

Build ui/index.html with 4-pane layout, sidebar, toolbar, status bar. CSS variables matching Windows 11 Fluent. No data yet — just layout skeleton with loading states.

~600 lines HTML+CSS

4

File Tree + Thumbnail Gallery (JS)

Virtual-scroll file list calling bridge.list_folder(). Lazy thumbnail loading via bridge.get_pdf_thumbnail() returning base64. Multi-select, drag, keyboard nav.

~800 lines JS

5

Preview Panel

PDF: PDF.js for render, zoom, page nav. Image: HTML5 canvas for display + crop overlay. Word/Excel: inject HTML from bridge into iframe. Text: contenteditable with autosave.

~600 lines JS

6

Right Panel + Rename Bar

File details, quick actions, rename input with template suggestion dropdown (autocomplete calling existing _filter_document_renames() logic via bridge).

~300 lines JS

7

Context Menu + Toolbar

Custom HTML context menu replicating all 25 existing right-click items. Toolbar with all existing actions. All wire to bridge methods.

~400 lines JS

8

Dialogs (9 modals)

HTML modal for each: CombinePdf, PdfFullView, ApostilleMatcher, A4PagePlacer, IdCardOnA4, PrintDialog, DocumentNameTemplates, UppercaseText, PdfPrintRange.

~1,200 lines JS+HTML

9

Excel Grid → AG-Grid or Handsontable

Replace ExcelGridFrame with a JS data grid. Bridge provides data via excel_to_html() or raw cell values. Sheet switching, sorting, basic editing calling excel_set_cell() via bridge.

~500 lines JS

10

AI Photo Editor Panel

HTML canvas panel replacing AIPhotoEditorFrame. Bridge exposes run_ai_photo_action(path, action, mask). Canvas shows before/after, confirm/replace.

~400 lines JS

11

Folder Maker Tab

Simple textarea + options panel replacing StudentFoldersFrame. Bridge create_folders() call. Live preview list. Progress log.

~250 lines JS

12

Watch Folder + Status Bar

Poll bridge.get_watch_entries() on interval. Status bar shows: Ready / folder / selection count / GPT cost / watch queue count.

~200 lines JS

Risks & Mitigations

RiskImpactMitigation
QR screen overlay (OverlaySelector) needs native window Medium Bridge spawns a minimal Tkinter overlay window in a thread, returns result to JS via callback
Windows native context menu (windows_shell_track_context_menu) Low Bridge calls the function directly; PyWebView windows are HWND-compatible
Long-running ops (Smart Split, OCR) block bridge thread High All long ops run in Python threads; bridge uses callback/event pattern to post progress to JS via window.evaluate_js()
PDF.js vs current PyMuPDF rendering parity Medium Bridge can still render pages to base64 PNG via PyMuPDF; PDF.js only used for display
ExcelGridFrame has 128 methods — complex cell editing Medium Phase 1: read-only HTML preview (excel_to_html). Phase 2: AG-Grid with cell edit calling excel_set_cell()
Clipboard integration (copy path, copy text) Low Bridge exposes set_clipboard(text) using Python pyperclip / win32clipboard
Drag & drop from Windows Explorer into app Medium PyWebView supports file drop events; bridge handles dropped paths
Printer dialog needs system printer list Low Bridge exposes list_printers() using win32print
